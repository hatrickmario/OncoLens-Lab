> después** (configuración/scripts: el test o el fixture en el mismo PR); `data-model.md` y readme

> No hay código de producto ni endpoints.
>
> **Secuencia de commits** (el orden de los commits manda sobre el número de sección; contract-keeper
> M2):
> 1. `contract(L1D-55): specs 3.1, schemas compartidos y ejemplos` — tareas 1.1–1.4.

>    del `chore` porque `assertDataModelDocument()` y `assertOperationsDeclarePermission()` leen

> 3. `chore(L1D-55): contracts:check y reglas` — tareas 1.5–1.6.
> 4. `chore(L1D-55): contracts:generate y extracto del readme` — tarea 1.7 (scripts).
> 5. `contract(L1D-55): código generado y extracto del readme` — tarea 1.7 (salida).
> 6. `test(L1D-55): reglas con parches de mutación` — tarea 1.8.
> 7. `refactor(L1D-55)` — tarea 1.10.
> Si una regla obliga a corregir un spec o un ejemplo después del commit 1, el arreglo va en otro
> commit `contract(L1D-55)` (tarea 1.9).
>
> **Excepciones declaradas:**
> - **Orden contract-first:** `contracts:check` y `contracts:generate` aún no existen cuando se
>   editan los specs (los crea este mismo change). La skill `sync-contracts` se sigue con la
>   comprobación manual equivalente de cada paso (lint con Redocly CLI fijado vía `npx`) y el
>   andamiaje del script va después del commit de los specs.
> - **Commit separado de lo generado** (contract-keeper m5): el código generado y el extracto del
>   readme van en su propio commit `contract(L1D-55)` (5), separado del `chore` que crea el
>   generador (4), para que el diff de lo generado se revise aparte y `contracts:generate:check`
>   pueda probarse sobre un árbol limpio.
> - **Sin `test` en rojo previo:** es test después (scripts y configuración), no TDD.
